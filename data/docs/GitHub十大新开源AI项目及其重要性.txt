从 MCP 到多智能体：GitHub 上目前十大新开源 AI 项目及其重要性

杰米·鲁伊斯（@ruizjeimy）｜2025年4月30日发布，2025年5月1日更新｜阅读约12分钟

每天都有新的公共和开源仓库出现在 GitHub 上，应对如此庞大的活动对我们来说都是一项挑战。幸运的是，我们已经帮你完成了繁重的工作。

我们与拥有开源和开发者关系经验的 GitHub 专家小组合作，分析了过去 99 天内（截至 2025 年 3 月 29 日）内创建的每个开源项目，并根据日星数、分叉次数、流量激增和贡献者速度等多个因素进行了排名。

我们的 GitHub 专家小组包括：

- Abigail Cabunoc Mayes（@abbycabs），负责开源维护程序，并担任 OpenJS 基金会的董事。
- Kara Sowles（@karasowles），与维护者和开源社区合作。
- Kevin Crosby（@kevincrosby），负责 GitHub 的开源资金项目。
- Jeff Luszcz（@jeffrey-luszcz），协助管理 GitHub 的开源程序办公室（OSPO）。

下面，我们将为您介绍这些项目，并讨论为什么我们认为这些项目是开发者不断回归的选择。让我们深入探讨。

一、顶级趋势一览

- 代理正变得至关重要：一年前的问题是"我可以微调哪个型号？"现在是"我能让哪个代理来做？"
- 模型上下文协议（MCP）正在帮助集成人工智能（并成为人工智能工具的 USB-C）：越来越多的项目通过 MCP 暴露它们的功能，这样任何 LLM 都能调用它们。
- 多智能体编排不再仅限于研究：像 OWL 这样的框架允许多个专业代理协作完成任务。
- 语音生成正在升级：项目将 TTS/STT 推向"朗读文本"，进入精确的时长控制以及自然的节奏和声音。
- 数字孪生实验数量不断增加：人们对能够跨应用传递你的上下文和声音的个人 AI 感兴趣。


二、十大新开源 AI 项目

1. Open WebUI MCP：简化 AI 工具集成

语言：Python｜@open-webui｜开源许可证：MIT 许可证

这是一个代理服务器，将 MCP 工具转变为兼容 OpenAPI 的 HTTP 服务器。开发 AI 驱动应用的开发者利用该服务器轻松连接基于 MCP 的工具与任何使用标准 RESTful OpenAPI 接口的设备。

为什么重要：Abigail 解释道："这个来自 OpenWebUI（2024 年 GitHub 加速器校友）的新项目，是人工智能集成趋势的一个很好的例子——尤其是其对 MCP 的应用。这凸显了人工智能领域的人们需要更多的整合，而像 MCP 这样的更多标准会有所帮助。"

2. Unbody："人工智能的 Supabase"

语言：TypeScript｜@unbody-io｜开源许可证：Apache 2.0 许可证

可以想象一下 Supabase，但针对 AI：这就是 Unbody 的缩影。它是一个模块化后端，让你构建真正理解并推理知识的 AI 原生软件，而不仅仅是简单地调整数据。

项目将内容分为四层，你可以自由搭配：

- 感知：获取、解析、增强和矢量化原始数据。
- 内存：将结构化知识存储在向量数据库和持久存储中。
- 推理：生成内容，调用函数，并规划操作。
- 行动：通过 API、SDK 和触发器暴露知识。

为什么重要：Kevin 提出一个有趣的问题："代理编码是如何从后端变得越来越抽象的？有了 Unbody，你可以在任何框架中编写，并获得自动管理的后端。如果你看看像端到端这样的公司，你会发现正在开发更先进的代理，展示后端堆栈是如何被抽象化的。"

3. OWL：多智能体协作的实际应用

语言：Python｜@camel-ai｜开源许可证：Apache 2.0 许可证

当一个 AI 代理不够时，OWL 会进入聊天。OWL 基于 CAMEL-AI 框架——该框架以推广多智能体角色扮演和发布大量合成"任务+数据"捆绑包而闻名——允许多个专业代理通过浏览器、终端、函数调用和 MCP 工具协作。它甚至在 GAIA 基准测试中登顶开源排行榜（58.18）。

为什么重要：Abigail 指出："它不仅是智能体的，还是像 OWL 这样的多模型和多智能体架构。一年前，一切都是人们构建模型——现在则全是代理及其能力。OWL 正在进行多代理工作，这正在迅速发展。"

4. f/mcptools：MCP 开发者的命令行功能

语言：Go｜@f｜开源许可证：MIT 许可证

CLI 爱好者们：这里有一个命令行界面，让你用来操作 MCP 服务器，感觉就像在家一样。由 GitHub 明星开发者 Fatih Kadir Akın 开发（他还发布了 GitHub Copilot 提示功能），它允许你发现和调用工具，访问资源，并管理任何兼容 MCP 的服务器提示。

MCP 工具支持通过 stdin/stdout 或 HTTP 输入输出，结果以 JSON 或表格视图形式输出。它甚至允许你创建模拟服务器用于测试，或者将 MCP 请求代理给 shell 脚本。

为什么重要：这让 MCP 变成了你可以"git clone 并调用 mcp"的状态。它提供了熟悉的 CLI 工作流程，并内置了保护模式，可以快速原型工具并锁定用于生产环境。

5. Nutlope/self.so：用 AI 在几秒钟内搭建你的个人网站

语言：TypeScript｜@Nutlope｜开源许可证：MIT 许可证

如果你觉得搭建个人网站不有趣，Nutlope/self.so 可以帮忙。上传你的简历或 LinkedIn 资料，工具会帮你整理一个简洁的网站，利用 AI 处理布局，让你省去 CSS 的麻烦。

技术栈包括用于语言建模的 Together.ai、Vercel 的 AI SDK、用于认证的 Clerk、用于框架的 Next.js、用于可观测性的 Helicone、用于存储的 S3、用于数据库的 Upstash Redis，以及用于托管的 Vercel。

为什么重要：该项目涉及可组合的"AI 乐高"堆栈。这是因为它将 Vercel AI SDK、Clerk 认证、Upstash Redis、S3 和 Tailwind 串联起来——每个服务都擅长完成一项任务——这说明现代 AI 应用往往是由小型专业服务拼接而成，而非整体化的。

6. VoiceStar：文本转语音应用的精确控制

语言：Python｜@jasonppy｜开源许可证：MIT 代码许可，CC-BY-4.0 模型许可

如果你的项目需要在特定时间窗口内完成语音，VoiceStar 可控时长的合成功能可以提供帮助。它允许开发者设定目标时长，使语音输出符合时间敏感的使用场景——如固定长度提示或旁白——而无需额外的音频编辑。

项目包含 CLI 和 Gradio 的推理接口，以及你可以立即使用的预训练模型。随着语音界面在应用中变得越来越重要，拥有这种开源的控制力模型是一个有益的进步。

为什么重要：它是一个开放的 TTS 模型，可以将语音固定到精确的时长——这对配音、广告和无障碍叠加非常有帮助，每一毫秒都至关重要。这是开源社区提供的 AI 辅助广播级时序。

7. Second-Me：创建你的数字孪生

语言：Python｜@mindverse｜开源许可证：Apache 2.0 许可证

想尝试用 AI 替代角色吗？Second-Me 让你尝试一个基础的"数字孪生"——一个旨在反映你知识、沟通风格和偏好的代理。

这些可能性从真正理解你思考的助理，到创新的方式与他人分享你的专业知识。Second-Me 的一个例子：让你的数字孪生管理你的 LinkedIn 或 Airbnb 账户，扮演专业人士或东道主的角色。

为什么重要：这正是我们看到的从模型向代理转变的一个典型例子。Jeff 解释道："如果我们看一年前，一切都是关于模型制作的。你是怎么做 X 或 Y 的？你会做一个新模型。这个项目以及榜单中的其他项目，都是向智能体转移以及人们如何利用人工智能来做事的转变。"

8. SesameAILabs/csm：重新构想语音合成

语言：Python｜@SesameAILabs｜开源许可证：Apache 2.0 代码许可（模型对滥用有限制）

会话语音模型（CSM）为语音生成带来了全新的方法。它通过基于 Llama 的架构将文本和音频输入转换为残差矢量化（RVQ）音频代码。其专用音频解码器生成的 Mimi 音频代码，使语音听起来出人意料地自然。

有趣的是，CSM 将语言模型架构与专业音频解码相结合——为你提供了一个开放的替代方案，替代市场上主导的专有文本转语音选项。

为什么重要：CSM 将基于 Llama 的文本骨干与轻量级音频解码器融合，后者输出 Mimi RVQ 代码——证明多模态混搭可以在单一 GPU 上本地运行。这告诉我们，模型级多模态开始采用 API 链，而宽松的 Apache-2.0 许可正在加速社区对十亿参数语音系统的研发。

9. Letta：便携式 AI 代理的通用标准

语言：Python｜@letta-ai｜开源许可证：Apache 2.0 许可证

Letta 引入了一种开放文件格式（.af），用于将 AI 代理打包，保持其内存和行为的完整。可以把它想象成一个代理的便携容器。你可以在不同框架上共享、检查点和版本控制。

对于同时管理多个代理框架的开发者来说，这可能节省了大量时间。想将代理从一个系统迁移到另一个系统而不从头重建？这正是 Letta 正在解决的问题。

值得注意的是，Letta 项目是 cpacker/memgpt 项目的分支——它衍生出了 MemGPT 最初用来快照其"虚拟上下文"代理的序列化层。团队将这些代码整理成一个干净、不依赖框架的规范（agent-file），使得任何技术栈——MemGPT/Letta、LangGraph、CrewAI 等——都能导入或导出一个完整有状态的代理，仅用一个 .af 压缩包。

为什么重要：可以想象成"AI 代理的 Docker 镜像"。.af 规范可以快照内存、工具和提示，让你能够在不同框架（MemGPT、LangGraph、CrewAI 等）之间进行版本控制、共享和热插拔代理，解决了"我该如何移动代理？"的难题。

10. Blender 遇见 Claude：连接 3D 创作与人工智能

语言：Python｜@ahujasid｜开源许可证：MIT 许可证

Blender 的艺术家们，这个给你们：一个第三方工具，通过 MCP 连接了流行的开源 3D 创作套件 Blender 和 Claude AI。通过 Blender-MCP，开发者可以用自然语言控制 Blender 操作，或在 3D 工作流程中添加 AI 辅助。

Blender-MCP 展示了 MCP 如何作为 LLM 代理的通用"工具接口"：如今它对接的是 Blender，明天可能会是 Unity、Unreal，或者任何复杂的桌面应用。对于 3D 艺术家和原型制作者来说，这意味着更快的场景搭建、简易的风格实验，以及全新的初学者教学方式。只要描述你想要什么，然后看软件如何构建它。

感兴趣吗？安装 Blender-MCP 只需运行一个 bash 命令即可。

为什么重要：这展示了 MCP 如何将 LLM 接入重型桌面应用——在这里，Claude 获得了 Blender 的自然语言场景创建和资产管理能力。其快速增长暗示 3D（甚至可能是 CAD、Unity、Unreal）的下一个用户体验飞跃可能会以聊天为主导。


三、这些项目告诉我们关于人工智能在开源领域的演变

这些模式不仅反映了开源 AI 的现状，也暗示了未来面临的挑战与机遇。以下是 GitHub 专家对这一快速发展领域的看法：

通过 MCP 与人工智能的集成是新的前沿

MCP 在多个项目中的突出地位凸显了标准化集成模式在人工智能开发中日益重要的地位。Abigail 指出："我看到的一个大趋势是人工智能与整合的痛点。更多像 MCP 这样的标准会有助于实现这一目标。"

多智能体协作的出现

像 OWL 这样的项目预示着未来，多个专业 AI 代理协同解决复杂问题。Kevin 解释道："你必须从人对人、代理对代理的结构中思考，然后让多个代理协同工作"，他强调了这种方法的复杂性和潜力。

语音生成技术正在进步

语音技术当然不是新鲜事——但大型语言模型正在如此剧烈地重塑文本转语音（TTS）和语音转文字（STT），一波新的可能性正在涌现。更大的故事是这在媒体、客户支持和产品用户体验等方面的影响。

开源参与的不断演变格局

人工智能吸引了新一波维护者和贡献者投入开源，带来了新的活力和方法。GitHub 开发者关系高级项目经理 Kara Deloss 指出："我们正在看到 AI 领域出现新一代维护者。"Kevin 补充说，"如果你在第一天就拥有庞大的社区，那是有价值的"，强调了生态系统正在演变。这种既有与新兴开发实践的融合，正在为社区内部的合作创造令人兴奋的机会。

OSI 批准许可证的重要性

我们名单上的每个顶级项目都使用 OSI 批准的许可证（主要是 MIT 和 Apache 2.0），这绝非偶然。Jeff 指出："一般来说，如果你自称开源但没有使用 OSI 批准的许可证，社区里不会给你太多正面评价。这些许可之所以重要，是因为它们对使用权、修改权和再分发权提供了明确保障，从而建立社区的信任。"

Jeff 还指出了一个新兴挑战："随着 AI 驱动的服务和工具变得更强大，我们看到一些项目对模型或服务使用施加了与滥用和欺诈相关的限制。这可能不会让它们在 OSI 批准的许可下完全开源，项目和社区将继续就这些条件进行深入讨论。"他继续说："在使用模型或服务之前，理解并记录任何限制非常重要。"这在开源 AI 社区应对不断演变的许可问题时，是一个及时的提醒。

探索并为未来的人工智能工具做出贡献

我们这里重点介绍的项目只是冰山一角。随着人工智能不断发展，开源生态系统是许多最令人兴奋的标准、工具和技术最先出现的地方。以下是参与的方式：

- 看看这些项目，看看它们如何融入你的工作流程
- 加入进来，参与激发你兴趣的项目
- 关注 MCP 及其他新兴标准
